# 跨资产关联导航 Skill

## 1. 功能范围

本 Skill 用于根据资产之间的结构化关系，从一个实体导航到另一类资产。

第一版支持：

* 板块 → 相关基金；
* 优选板块 → 相关基金；
* 基金 → 重仓股票；
* 基金 → 行业、板块和资产配置；
* 基金 → 成长价值风格和市值风格；
* 股票 → 行业、概念和公司画像；
* 板块 → 基金 → 基金重仓股票、行业和风险画像。

本 Skill 只展示当前工具明确返回的关联关系，不根据模型记忆补充股票、基金、指数或关联权重。

---

## 2. When to Use

当用户提出以下问题时，使用本 Skill：

### 板块到基金

* 半导体板块有哪些相关基金？
* 机器人方向有哪些基金？
* 白酒板块对应哪些基金？
* 最近优选板块中有哪些相关基金？

### 基金到股票、行业和风格

* 这只基金主要持有哪些股票？
* 005827 的重仓股是什么？
* 这只基金主要配置哪些行业？
* 这只基金偏成长还是价值？
* 这只基金属于大盘还是小盘风格？
* 这只基金对哪些板块暴露较多？

### 股票到行业和概念

* 宁德时代属于什么行业？
* 这只股票主要关联什么赛道？
* 贵州茅台有哪些行业或概念属性？

### 组合链路

* 机器人板块有哪些相关基金，这些基金主要持有什么？
* 半导体相关基金中，哪些历史波动相对较低？

---

## 3. When NOT to Use

以下问题不要用本 Skill 直接完成：

1. 查询板块完整成分股。
2. 查询某只股票被哪些基金持有。
3. 查询指数完整成分股和成分权重。
4. 查询跟踪某指数的全部基金。
5. 查询股票属于哪些完整指数。
6. 计算基金或股票的 Beta 暴露度。
7. 全市场筛选股票或基金。
8. 明确要求推荐买入某只股票或基金。
9. 要求交易执行、加仓、减仓或卖出。
10. 要求根据个人持仓或风险偏好提供个性化建议。

超出范围时，应明确说明当前工具缺少对应的结构化关系数据，不得自行生成结果。

## 4. 场景识别与工具路由

| 用户意图          | 优先 Tool                   | 用途                    |
| ------------- | ------------------------- | --------------------- |
| 查询优选板块        | `queryTopBoard_7223`      | 获取系统返回的优选板块列表         |
| 板块画像或板块分析     | `queryBoardAnalysis_7221` | 补充板块技术面、基本面和 PEST 等分析 |
| 板块 → 相关基金     | `queryBoardFund_7222`     | 查询与板块相关的基金            |
| 基金 → 股票、行业、风格 | `queryKypInfo_3107`       | 获取基金重仓股、行业、板块、资产配置和风格 |
| 股票 → 行业、概念画像  | `queryStockKypInfo_7192`  | 获取股票行业属性、公司画像和相关概念    |
| 模糊基金名称解析      | `queryFundCodes_7361`     | 查询基金代码候选，再回查标准名称      |

工具调用原则：

1. 优先调用直接返回结构化关系的 Tool。
2. `queryBoardFund_7222` 是板块到基金的核心工具。
3. `queryKypInfo_3107` 是基金向下穿透的核心工具。
4. `queryBoardAnalysis_7221` 只用于补充板块画像，不替代板块基金关系。
5. `queryTopBoard_7223` 只用于发现优选板块，不代表未来上涨。
6. 不得将分析文本中偶然出现的股票或基金当作正式关联结果。

## 5. 实体识别规则

### 5.1 板块名称

用户提供“半导体”“机器人”“白酒”等名称时，提取为 `boardName`。

示例：

```json
{
  "boardName": "半导体"
}
```

如果工具未识别该板块，或返回结果与用户输入明显不一致，应提示用户提供更准确的板块名称。

不得自行将宽泛主题强制映射为某个板块。

### 5.2 基金名称或代码

如果用户提供明确的六位基金代码，可以直接调用 `queryKypInfo_3107`。

```json
{
  "fundCodeList": ["005827"]
}
```

如果用户只提供基金简称或模糊名称：

1. 调用 `queryFundCodes_7361` 获取候选代码；
2. 使用 `queryKypInfo_3107` 回查标准名称；
3. 检查是否与用户输入一致。

返回多个候选时，应先让用户确认，不得默认选择第一个结果。

### 5.3 股票名称或代码

股票名称明确时，可直接调用 `queryStockKypInfo_7192`。

```json
{
  "skShortNameList": ["宁德时代"]
}
```

如果返回对象与用户输入不一致，应先确认股票对象，不得继续生成关联结论。

## 6. 公共协议参数

`requestId`、`pin`、`extParams` 属于 MCP Gateway 公共协议字段，原则上由系统层或运行环境自动填充。

Skill 只负责业务参数构造，不向用户展示或编造用户身份信息。

---

## 7. 返回结果解析规则

财富 MCP Tools 通常返回统一外层结构：

```json
{
  "code": "...",
  "success": true,
  "message": "...",
  "class": "...",
  "data": "..."
}
```

处理规则：

1. 先检查 `success` 和 `code`。
2. `data` 为字符串时，应二次解析为 JSON。
3. 检查返回实体名称和代码是否与用户对象一致。
4. 提取关系对应的关键字段，不展示完整原始 JSON。
5. 关联权重、持仓比例、数据日期等字段只有工具返回时才能使用。
6. 字段缺失时明确标注，不得自行推断。
7. 不展示 MCP URL、内部 class、debug 信息或协议参数。
8. 不把接口返回的交易策略和操作建议作为关联结果输出。

## 8. 工作流策略：六步跨资产关联导航法

### Step 1：识别起点实体和目标类型

先识别用户从什么实体出发，以及希望查询什么关系。

第一版支持：

| 起点   | 目标         |
| ---- | ---------- |
| 板块   | 相关基金       |
| 优选板块 | 相关基金       |
| 基金   | 重仓股票       |
| 基金   | 行业、板块和风格   |
| 股票   | 行业和概念画像    |
| 板块   | 基金，再穿透基金持仓 |

如果用户目标是指数成分、股票反查基金或 Beta 暴露，应说明当前暂不支持。

---

### Step 2：确认实体对象

确认板块、基金或股票的标准名称和代码。

处理规则：

1. 代码明确时优先使用代码。
2. 名称唯一且高度一致时可以继续。
3. 返回多个候选时先请用户确认。
4. 返回对象与用户输入明显不一致时停止后续调用。
5. 不得根据模型记忆自行生成证券代码或基金代码。

---

### Step 3：获取直接关联关系

#### 基金经理 → 旗下基金持仓

调用 `queryFundCodes_7361`：

```json
{
  "query": "泽丰哥管理的基金"
}
```

步骤：

1. 获取基金经理管理的基金候选列表；
2. 对每只基金调用 `queryKypInfo_3107`，提取重仓股票、行业配置和风格；
3. 按基金分组展示持仓分布；
4. 如某只基金查询失败，标注"该基金的持仓信息暂未成功返回"。

约束：

* 不做全市场扫描，只用工具返回的候选基金列表。
* 不根据模型记忆补充未返回的基金或持仓。
* 持仓数据以工具返回的报告期为准。

#### 板块 → 基金

调用 `queryBoardFund_7222`：

```json
{
  "boardList": ["半导体"],
  "isExchangeFund": false
}
```

提取：

* 板块名称；
* 相关基金名称；
* 基金代码；
* 工具返回的夏普率等字段。

结果应表述为“当前系统查询到的相关基金”，不代表全市场完整列表。

#### 基金 → 股票、行业和风格

调用 `queryKypInfo_3107`，提取：

* 资产配置；
* 前十大重仓股；
* 持仓权重；
* 行业配置；
* 重仓申万行业；
* 重仓板块；
* 成长价值风格；
* 市值风格。

#### 股票 → 行业和概念

调用 `queryStockKypInfo_7192`，提取：

* 股票名称和代码；
* 所属行业；
* 公司业务画像；
* 工具明确返回的概念或板块属性。

---

### Step 4：判断关联依据

关联关系分为三类。

#### 直接关系

工具明确返回的：

* 板块关联基金；
* 基金重仓股票；
* 基金行业配置；
* 基金资产配置。

可以直接展示。

#### 画像关系

工具根据产品或股票特征返回的：

* 成长价值风格；
* 市值风格；
* 股票行业属性；
* 股票概念或赛道画像。

应表述为“画像显示”或“工具返回的属性”。

#### 无法确认的关系

包括：

* 未返回持仓权重；
* 未返回行业占比；
* 未返回指数成分关系；
* 未返回 Beta 数据；
* 只在分析文本中偶然提及某个资产。

此类关系不得包装为确定性结论。

---

### Step 5：补充目标资产画像与风险

当用户从板块导航到基金时，可继续调用 `queryKypInfo_3107` 补充：

* 基金类型；
* 基金规模；
* 收益表现；
* 最大回撤；
* 波动率；
* 夏普率；
* 基金经理；
* 重仓股和行业配置。

补充数据用于帮助用户理解各相关基金的差异。

不得因为某只基金收益率或夏普率较高，就直接表述为“最值得购买”。

如果用户要求比较多个关联基金，应按多基金对比方法处理。

---

### Step 6：输出关联结果和能力边界

输出应包括：

1. 起点实体；
2. 查询到的目标资产；
3. 关联依据；
4. 权重、占比或排名；
5. 数据日期；
6. 当前能力边界。

推荐表达：

* 根据工具返回的板块基金关系，当前查询到以下相关基金。
* 从基金最新持仓看，其主要重仓股票包括……
* 从行业配置看，该基金主要暴露于……
* 从风格画像看，该基金偏向成长或大盘风格。
* 当前工具未返回精确权重，因此只能确认存在关联，无法判断关联强弱。
* 当前结果不代表全市场完整股票或基金列表。

不得输出：

* 这是最好的相关基金；
* 某只股票一定是板块龙头；
* 建议购买某只股票或基金；
* 未经工具支持的关联强度分数；
* 工具未返回的指数权重、持仓比例或 Beta 值。

---

## 9. 各场景关键字段

### 板块 → 基金

优先提取：

* 板块名称；
* 基金名称和代码；
* 基金类型；
* 夏普率；
* 基金主要行业和重仓方向；
* 数据日期。

### 基金 → 股票

优先提取：

* 基金名称和代码；
* 重仓股票；
* 持仓权重；
* 持仓日期；
* 资产配置。

如果工具只返回重仓股票文本，不得自行补充精确持仓比例。

### 基金 → 行业、板块和风格

优先提取：

* 主要行业；
* 行业配置比例；
* 重仓板块；
* 成长价值风格；
* 市值风格；
* 股票、债券和现金比例。

### 股票 → 行业和概念

优先提取：

* 股票名称和代码；
* 所属行业；
* 主营业务；
* 相关概念或板块；
* 工具返回的公司画像。

不得将资讯或模型常识中的概念当作结构化归属。

## 10. 输出规范

### 推荐输出结构

```text
一、关联对象
- 起点：半导体板块
- 目标：相关基金

二、当前查询结果
| 基金 | 代码 | 关联依据 | 主要行业/持仓 | 风险特征 |
| --- | --- | --- | --- | --- |

三、关系说明
- 基金 A 与该板块的关联主要来自……
- 基金 B 的相关行业暴露为……

四、风险与边界
- 当前结果为系统返回的相关基金，不代表全市场完整名单。
- 历史持仓可能发生变化。
- 以上为关联关系展示，不构成投资建议。
```

总体要求：

1. 优先用表格展示多个目标资产。
2. 说明每项关联的具体依据。
3. 有权重时展示权重，无权重时不判断关联强弱。
4. 标注数据日期或报告期。
5. 区分板块关联、持仓关系和画像关系。
6. 不编造工具未返回的股票、基金、指数或权重。
7. 不输出个性化推荐和交易决策。

## 12. 错误与降级处理

### 板块未识别

1. 说明当前工具未识别该板块。
2. 可提示用户提供更标准的行业或板块名称。
3. 不自行选择相近板块替代。

### 基金名称不明确

1. 调用 `queryFundCodes_7361` 获取候选。
2. 展示候选基金名称和代码。
3. 用户确认前不继续穿透持仓。

### 工具未返回关联结果

明确说明：

> 当前工具未查询到该实体对应的结构化关联关系。

不得使用模型记忆或互联网常识补全。

### 权重或占比缺失

可以展示关联对象，但应说明：

> 当前工具未返回具体权重，无法判断各资产的精确关联强度。

不得将字段缺失解释为权重为零。

### 部分工具失败

如果板块基金关系已经成功返回，但基金画像补充失败：

1. 可以展示相关基金名单；
2. 说明部分收益、风险或持仓信息暂未成功返回；
3. 不影响已确认的直接关系；
4. 不编造缺失画像。

## 13. 示例流程

### 示例 1：板块到基金

用户：

> 半导体板块有哪些相关基金？

流程：

1. 识别起点为半导体板块，目标为相关基金。
2. 调用 `queryBoardFund_7222`。
3. 提取相关基金名称、代码和夏普率等字段。
4. 必要时调用 `queryKypInfo_3107` 补充基金风险和持仓。
5. 输出相关基金及关联依据，不做购买推荐。

---

### 示例 2：优选板块到基金

用户：

> 最近优选板块有哪些对应基金？

流程：

1. 调用 `queryTopBoard_7223` 获取优选板块。
2. 展示板块并根据用户指定对象调用 `queryBoardFund_7222`。
3. 必要时调用 `queryKypInfo_3107` 补充基金画像。
4. 说明优选板块不代表未来一定上涨。

---

### 示例 3：基金到股票

用户：

> 005827 主要持有哪些股票？

流程：

1. 确认基金代码。
2. 调用 `queryKypInfo_3107`。
3. 提取重仓股票、持仓权重和持仓日期。
4. 按权重或工具返回顺序展示。
5. 提示基金持仓会随定期报告更新。

---

### 示例 4：基金到行业和风格

用户：

> 这只基金主要暴露在哪些行业，偏成长还是价值？

流程：

1. 确认基金对象。
2. 调用 `queryKypInfo_3107`。
3. 提取行业配置、重仓板块、成长价值风格和市值风格。
4. 区分实际持仓和风格画像。
5. 未返回比例时不判断精确暴露强度。

---

### 示例 5：股票到行业概念

用户：

> 宁德时代属于什么行业和赛道？

流程：

1. 调用 `queryStockKypInfo_7192`。
2. 提取所属行业、主营业务和工具返回的概念画像。
3. 不扩展为完整指数归属。
4. 不根据公司行业属性推荐股票。

---

### 示例 6：当前不支持的关系

用户：

> 哪些基金重仓宁德时代？

流程：

1. 判断为股票反查基金。
2. 当前没有股票持仓基金反向查询 Tool。
3. 明确说明暂不支持完整查询。
4. 不通过逐只基金扫描或模型记忆生成基金名单。
