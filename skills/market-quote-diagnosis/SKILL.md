# 盘中/盘后行情解读 Skill

## 1. 功能定位

本 Skill 用于处理市场或板块层面的行情解读问题。

核心目标是：当用户看到市场上涨、下跌、震荡或某个板块异动时，基于 MCP Tool 返回的行情事实、市场研判、资讯背景和板块结构，解释“发生了什么”“可能由什么驱动”“后续需要关注什么”。

本 Skill 不是单纯查数，也不是深度投研报告。
本 Skill 不直接输出买入、卖出、加仓、减仓、清仓等交易建议，不承诺收益，不预测具体点位。

---

## 2. 功能范围

本 Skill 支持以下场景：

1. 市场涨跌解读
   解释 A 股、港股、美股等市场当日或近期涨跌现象。

2. 市场状态概览
   结合涨跌家数、指数表现、强弱板块，说明市场当前状态。

3. 市场研判
   基于工具返回的当前、短期、中期、长期市场研判，解释市场可能处于什么环境。

4. 板块结构观察
   识别涨幅较强或跌幅较大的板块、赛道或行业。

5. 单板块研判
   当用户明确询问某个板块，如白酒、新能源、半导体、医药等，结合板块研判工具输出技术面、基本面或事件背景。

6. 资讯背景补充
   当用户问“为什么”“出什么事了”“有什么热点”时，使用 RAG 资讯补充近期新闻、观点或事件背景。

---

## 3. When to Use

当用户提出以下问题时，使用本 Skill：

### 市场行情解读

* 今天市场为什么跌？
* 今天 A 股怎么了？
* 今天市场红了，是什么带动的？
* 最近 A 股怎么看？
* 大盘最近为什么波动这么大？
* 美股最近怎么看？
* 港股今天为什么涨？

### 市场状态概览

* 今天市场整体怎么样？
* 今天赚钱效应怎么样？
* 市场现在是普涨还是分化？
* 今天涨跌家数怎么样？
* 今天哪些方向比较强？

### 热点与资讯背景

* 最近市场热点是什么？
* 最近有什么热门投资话题？
* 今天有什么利好或利空？
* 是不是有什么消息影响了市场？

### 板块行情解读

* 白酒板块最近怎么看？
* 新能源板块为什么跌？
* 半导体今天为什么涨？
* 医药板块最近有什么变化？
* 最近哪些板块比较强？
* 有哪些优选板块？

---

## 4. When NOT to Use

以下问题不要使用本 Skill 直接完成：

1. 单纯查数

   * 上证指数现在多少点？
   * 白酒板块今天涨跌幅是多少？
   * 贵州茅台现在多少钱？

   应转入 `financial-indicator-query`。

2. 单只基金综合评测

   * 005827 这只基金怎么样？
   * 这只基金风险大吗？
   * 这只基金最近为什么跌？

   应转入 `fund-comprehensive-eval`。

3. 股票个股深度分析

   * 贵州茅台基本面怎么看？
   * 宁德时代值不值得买？
   * 某只股票目标价是多少？

   应转入股票研究类 Skill。

4. 基金推荐、股票推荐、板块选基、指标选股

   * 最近买什么基金？
   * 推荐几只新能源基金。
   * 帮我筛选高股息股票。

5. 交易执行或交易建议

   * 现在要不要买？
   * 要不要加仓？
   * 帮我卖出。
   * 设置止盈止损。

6. 用户持仓、KYC、资产配置、个性化建议

   * 我的持仓怎么办？
   * 我的风险偏好适合买什么？
   * 帮我做资产配置方案。

如用户问题超出范围，应说明本 Skill 仅支持公开市场和板块行情解读，不提供个性化投资建议或交易指令。

## 5. MCP Tools 路由规则

用户意图 | 优先 Tool | 用途
--- | --- | ---
市场涨跌概览 | `queryMarketOverview` | 获取涨跌家数、涨幅 TOP3 赛道、跌幅 TOP3 赛道
市场 / 指数行情事实 | `queryMarketData` | 查询 A 股、港股、美股、指数、积存金等行情数据
市场深度研判 | `queryMarketAnalysis` | 获取当前、短期、中期、长期市场研判及原因
市场热点 / 新闻背景 | `search` | 查询资讯标题、正文、来源、时间，作为 RAG 背景补充
优选 / 强势板块 | `queryTopBoard` | 获取优选板块或强势板块列表
单板块研判 | `queryBoardAnalysis` | 获取板块技术面、基本面、PEST、SWOT、波特五力等分析

工具使用原则：

1. 用户问“今天市场怎么样 / 为什么涨跌”时，优先使用 `queryMarketOverview` 和 `queryMarketAnalysis`。
2. 用户问具体市场或指数行情时，可使用 `queryMarketData` 补充事实。
3. 用户问“最近热点 / 出什么事了 / 为什么”时，可使用 `search` 补充资讯背景。
4. 用户问“哪些板块强 / 市场主线是什么”时，使用 `queryTopBoard`。
5. 用户明确问某个板块时，使用 `queryBoardAnalysis`。
6. 板块工具只用于行情结构和归因辅助，不用于直接推荐基金或股票。
7. 不调用推荐、筛选、交易、持仓、KYC、用户画像类工具。

## 6. 参数构造规则

### 6.1 无业务参数 Tool

适用 Tools：

* `queryMarketOverview`
* `queryTopBoard`

规则：

1. 无需构造业务参数。
2. 如运行环境要求公共协议字段，由系统层填充。
3. 返回结果只作为市场状态或板块结构事实，不直接作为买卖依据。

---

### 6.2 自然语言 query 型 Tool

适用 Tools：

* `queryMarketData`
* `search`

规则：

1. 从用户问题中提取市场、指数、板块、事件、时间范围。
2. 保留用户原意，不做过度扩写。
3. 将整理后的自然语言放入 `query` 字段。
4. `search` 如支持 `maxSize`，默认取 3-5 条，不需要返回过多资讯。

示例：

用户问：

> 今天 A 股怎么样？

构造：

```json
{
  "query": "查询今天A股市场行情和主要指数表现"
}
```

用户问：

> 最近市场热点是什么？

构造：

```json
{
  "query": "近期A股市场热点和主要财经话题",
  "maxSize": 5
}
```

用户问：

> 今天 A 股为什么跌？

构造：

```json
{
  "query": "今日A股下跌原因和相关市场资讯",
  "maxSize": 5
}
```

---

### 6.3 结构化业务参数 Tool

适用 Tools：

* `queryMarketAnalysis`
* `queryBoardAnalysis`

#### 市场分析：`queryMarketAnalysis`

业务参数：

* `assetType`

规则：

1. 用户说 A 股、大盘、沪深、创业板、上证、深成指，默认 `assetType=["A股"]`。
2. 用户说港股、恒生、恒指，传 `assetType=["港股"]`。
3. 用户说美股、纳指、标普、道指，传 `assetType=["美股"]`。
4. 用户同时问多个市场，可传多个值，如 `["A股", "美股"]`。
5. 不确定市场类型时，应先根据上下文判断；仍不明确时追问。

示例：

```json
{
  "assetType": ["A股"]
}
```

---

#### 板块研判：`queryBoardAnalysis`

业务参数：

* `boardCode` 或 `boardName`

规则：

1. 用户明确提到板块名称时，优先使用 `boardName`。
2. 如用户提供板块代码，可使用 `boardCode`。
3. 用户未明确板块时，不调用 `queryBoardAnalysis`，可先调用 `queryTopBoard` 获取强势板块列表。
4. 不得将板块研判结果直接转化为基金或股票推荐。

示例：

```json
{
  "boardName": "白酒"
}
```

## 7. 公共协议参数

`requestId`、`pin`、`extParams` 属于 MCP Gateway 层公共协议字段，原则上由系统层或运行环境自动填充。

Skill 只负责业务参数构造，不向用户暴露这些字段。

如运行环境要求显式传入：

* `requestId`：由 Agent 或系统生成。
* `pin`：默认不手动构造，不编造用户身份。
* `extParams`：无特殊要求时传空对象 `{}`。

## 8. 返回结果解析规则

财富 MCP Tools 通常返回统一外层结构：

```json
{
  "code": "...",
  "success": true,
  "message": "...",
  "class": "...",
  "data": "..."
}
```

处理规则：

1. 先检查 `success`。
2. 再检查 `code`。
3. 如果 `success=false` 或 `code` 表示失败，读取 `message`，说明工具未成功返回，不得自行补数据。
4. `data` 通常是字符串，应二次解析为 JSON。
5. 如果 `data` 无法解析为 JSON，则按文本结果处理。
6. 不展示完整原始 JSON，除非用户明确要求。
7. 只提取与用户问题直接相关的字段。
8. 字段缺失时说明“当前工具未返回该字段”，不得猜测。
9. 不向用户展示 MCP URL、接口路径、内部 class、debug 信息。

## 9. 行情解读方法论

本 Skill 使用“五步行情解读法”。

### Step 1：行情事实

先说明工具返回的市场事实：

* 目标市场或板块；
* 主要指数表现；
* 涨跌家数；
* 涨幅 TOP 赛道；
* 跌幅 TOP 赛道；
* 实时点位、涨跌幅、成交额等；
* 数据时间。

如果工具未返回某字段，不得编造。

---

### Step 2：市场研判

结合 `queryMarketAnalysis` 返回结果，提取：

* 当前市场研判；
* 短期研判；
* 中期研判；
* 长期研判；
* 工具返回的主要原因。

处理规则：

1. 不直接把长期研判当成短期交易建议。
2. 不把工具中的观点扩写成确定性预测。
3. 多周期研判不一致时，应说明不同时间维度可能存在差异。

---

### Step 3：原因拆解

结合市场研判和资讯 RAG，从以下维度解释可能原因：

* 政策变化；
* 海外市场；
* 利率、汇率、通胀等宏观因素；
* 行业事件；
* 资金情绪；
* 市场风险偏好；
* 板块轮动；
* 突发新闻或事件。

处理规则：

1. 原因必须来自工具返回结果。
2. 不得脱离工具结果编造利好、利空或政策消息。
3. 如果工具信息不足，应使用“可能与……有关”“仍需观察”等不确定表达。
4. RAG 资讯只作为背景补充，不替代行情和研判数据。

---

### Step 4：板块结构

结合 `queryMarketOverview`、`queryTopBoard`、`queryBoardAnalysis` 返回结果，说明：

* 哪些板块相对强势；
* 哪些板块拖累市场；
* 是否存在明显主线；
* 单板块的技术面、基本面或事件线索；
* 板块分化是否明显。

处理规则：

1. 板块强弱不等于推荐买入。
2. 优选板块只能表述为“相对强势 / 值得观察”，不得表述为“建议买入”。
3. 单板块研判只能解释板块情况，不自动延伸到基金或个股推荐。

---

### Step 5：风险提示与后续关注

最后给出风险提示和后续关注点。

可关注：

* 成交额是否放大；
* 涨跌家数是否改善；
* 领涨板块是否持续；
* 外部事件和政策变化；
* 市场研判是否发生变化；
* 资讯中提到的关键风险是否继续发酵。

禁止输出：

* 建议买入；
* 建议卖出；
* 可以加仓；
* 应该减仓；
* 适合满仓；
* 赶紧上车；
* 清仓规避；
* 给出确定性点位预测。

---

## 10. 大 JSON / 多来源结果处理规则

当 Tool 返回较大 JSON 或多来源内容时，不完整复述，只提取关键字段。

### 市场概览类

从 `queryMarketOverview` 优先提取：

* 涨跌家数；
* 涨幅 TOP3 赛道；
* 跌幅 TOP3 赛道；
* 数据时间，如返回。

### 市场行情类

从 `queryMarketData` 优先提取：

* 指数名称；
* 指数代码；
* 实时点位；
* 涨跌幅；
* 成交额；
* 市场类型；
* 数据时间；
* 积存金价格，如用户询问黄金/积存金相关行情。

### 市场研判类

从 `queryMarketAnalysis` 优先提取：

* assetType；
* 当前研判；
* 短期研判；
* 中期研判；
* 长期研判；
* 工具返回的原因；
* 风险提示。

### RAG 资讯类

从 `search` 优先提取：

* 标题；
* 正文摘要；
* 来源；
* 发布时间；
* 与用户问题最相关的 2-3 条资讯。

### 优选板块类

从 `queryTopBoard` 优先提取：

* rankId；
* boardCode；
* boardName。

### 板块研判类

从 `queryBoardAnalysis` 优先提取：

* boardName / boardCode；
* 技术面分析；
* 基本面分析；
* PEST；
* SWOT；
* 波特五力；
* 风险提示，如返回。

## 11. 模糊匹配处理规则

部分 Tools 可能自带模糊匹配，并默认返回相似度最高结果。

处理原则：

1. 如果返回对象与用户输入高度一致，可以继续解读。
2. 如果返回对象与用户输入不完全一致，应说明“系统匹配到的是 xxx”。
3. 如果返回多个候选，应列出候选并请用户确认。
4. 如果只返回一个候选，但名称、代码、类型与用户输入明显不一致，应向用户确认。
5. 标的不确定时，不得继续调用后续分析工具。
6. 不得默认选择第一个候选作为最终对象，除非返回结果明确说明该对象为唯一高置信匹配。

## 13. 输出规范

### 总体要求

1. 不展示技术字段名、原始 JSON、内部 class、debug 信息。
2. 不展示 MCP URL、接口路径、系统调用细节。
3. 不编造工具未返回的数据或新闻。
4. 不直接输出买入、卖出、清仓、满仓、加仓、减仓等交易建议。
5. 不使用“稳赚”“保本”“必涨”“一定上涨”等确定性表述。
6. 涉及行情、价格、点位时，应展示数据时间。
7. 资讯内容需要说明来源或时间，如工具返回。
8. 输出面向普通用户，避免过度投研术语。
9. 输出结构可根据用户问题灵活调整，但必须回答用户问的核心问题。

## 14. 错误处理

### 工具调用失败

如果 Tool 返回失败：

1. 说明工具未成功返回。
2. 可展示 `message` 中适合用户理解的信息。
3. 不编造行情、点位、涨跌幅、新闻事件或市场原因。
4. 可建议用户换更明确的市场、板块或时间范围。

### data 解析失败

如果 `data` 字段无法二次解析：

1. 如果 data 是可读文本，则基于文本摘要回答。
2. 如果 data 不可读，则说明当前返回结果无法解析。
3. 不把不可解析内容包装成确定性数据。

### 信息不足

如果工具返回信息不足：

1. 明确说明“当前工具返回的信息不足以支持完整解释”。
2. 可以给出一般观察框架。
3. 不输出具体涨跌原因或投资判断。

### 多来源结果冲突

如果不同工具返回的观点不一致：

1. 优先区分事实数据和观点判断。
2. 行情事实以行情类工具为准。
3. 原因解释以市场分析和资讯背景为参考。
4. 输出时说明“不同来源侧重点不同”。

## 15. 示例流程

### 示例 1：A 股市场下跌解读

用户：

> 今天市场为什么跌？

流程：

1. 判断为市场涨跌解读。
2. 调用 `queryMarketOverview` 获取涨跌家数、涨跌赛道。
