# 金融指标查询 Skill

## 1. 功能定位

本 Skill 只处理“查数 / 查字段 / 查指标”类问题。

核心目标是：根据用户问题识别查询对象和指标，调用对应 MCP Tool，返回工具结果中的关键字段。

本 Skill 不做分析解释，不做原因归因，不做推荐判断，不做交易建议。

---

## 2. 支持查询对象

支持以下公开金融对象的指标查询：

1. 基金：基金基础字段、KYP 字段、实时估值、净值、风险等级、基金经理、基金类型等。
2. 股票 / 指数：实时价格、涨跌幅、成交额、行情字段、股票 KYP 字段等。
3. 黄金：实时金价、历史金价、金价单位、涨跌幅、报价时间等。
4. 市场 / 板块 / 指数：仅支持明确的数值型指标查询，例如点位、涨跌幅、成交额等。

---

## 3. When to Use

当用户明确想查询某个对象的某个数值、字段、状态时，使用本 Skill。

### 基金指标查询

示例：

* 005827 现在估值多少？
* 查一下 005827 的风险等级。
* 这只基金的基金经理是谁？
* 招商中证白酒指数 A 的基金类型是什么？
* 005827 的单位净值是多少？

### 股票 / 指数指标查询

示例：

* 贵州茅台现在多少钱？
* 600519 今天涨跌幅是多少？
* 上证指数现在多少点？
* 沪深 300 今天涨跌多少？
* 查询宁德时代的PE。

### 黄金指标查询

示例：

* 现在金价多少？
* 积存金价格是多少？
* 黄金今天涨跌幅是多少？
* 查询最近一段时间黄金价格。

### 市场 / 板块数值查询

示例：

* 白酒板块今天涨跌幅是多少？
* A 股主要指数当前点位是多少？
* 创业板指数今天成交额是多少？

---

## 4. When NOT to Use

以下问题不要使用本 Skill 直接完成：

1. 行情诊断或涨跌原因解释

   * 今天市场为什么跌？
   * 白酒板块最近怎么看？
   * 黄金为什么上涨？

2. 投资研究或深度分析

   * 帮我分析一下这只基金怎么样。
   * 宁德时代基本面怎么看？
   * 半导体板块景气度如何？

3. 买卖推荐或交易决策

   * 这只基金能买吗？
   * 现在该不该买黄金？
   * 贵州茅台要不要加仓？

4. 筛选 / 推荐 / 选基 / 选股

   * 帮我找几只低回撤基金。
   * 帮我筛选高股息股票。
   * 看好新能源，买哪只基金？

5. 用户个性化能力

   * 查询 KYC、用户画像、用户记忆、个人指标。
   * 查询持仓收益、理财周报、资产配置建议。

6. FAQ / 概念解释 / 资讯 RAG

   * 什么是最大回撤？
   * 最近有哪些市场热点？
   * 某个事件有什么影响？

如用户问题超出本 Skill 范围，应说明当前 Skill 仅支持指标查询，并引导到对应的分析研究、筛选、推荐、资讯或持仓类 Skill。

---

## 5. 场景识别与工具路由

收到用户请求后，先识别：

1. 查询对象：基金 / 股票 / 指数 / 黄金 / 市场 / 板块。
2. 查询指标：价格、涨跌幅、估值、净值、风险等级、基金经理、规模、PE、PB、成交额等。
3. 查询标识：代码、名称、简称、指数名、板块名。
4. 时间范围：实时、今日、近一周、历史区间等。

然后按下表选择 Tool：

| 用户意图 | 优先 Tool | 业务参数构造 |
| :--- | :--- | :--- |
| 基金基础字段 / KYP 字段 | `queryKypInfo` | 提取 `fundCodeList` 或 `fundNameList`，并传 `pageSize`、`currentPage` |
| 基金实时估值 | `queryFundValuation` | 提取 `fundCodes` |
| 股票基础字段 / 股票 KYP | `queryStockKypInfo` | 提取 `skShortNameList` 或 `skInnerCodeList` |
| 股票 / 指数实时或历史行情 | `querySecuQuote` | 提取 `secuNames` 或 `secuCodes` |
| 黄金实时或历史价格 | `queryGoldPrice` | 按 Tool 入参要求传黄金查询条件 |
| 市场 / 板块 / 行业明确数值指标 | `queryMarketData` | 从用户问题提取 `query`，仅用于明确查数，不用于行情解读 |

---

## 6. 参数构造规则

### 6.1 结构化业务参数型 Tool

以下 Tools 不能只传自然语言 `query`，必须抽取业务参数。

#### 基金 KYP：`queryKypInfo`

适用：

* 基金名称、代码、类型、风险等级、基金经理、规模、成立日期、基础画像等字段查询。

必填业务参数：

* `fundCodeList` 或 `fundNameList`

示例：

```json
{
  "fundCodeList": ["005827"]
}
```

或：

```json
{
  "fundNameList": ["招商中证白酒指数A"]
}
```

#### 基金估值：`queryFundValuation`

适用：

* 基金实时估值、估值涨跌幅、估值时间等字段查询。

业务参数：

* `fundCodes`

如果用户只提供基金名称，应先使用 `queryKypInfo` 获取基金代码，再调用 `queryFundValuation`。

示例：

```json
{
  "fundCodes": ["005827"]
}
```

#### 股票 KYP：`queryStockKypInfo`

适用：

* 股票基础画像、公司名称、所属行业、市值、估值指标等字段查询。

业务参数：

* `skShortNameList` 或 `skInnerCodeList`

示例：

```json
{
  "skShortNameList": ["贵州茅台"]
}
```

#### 证券行情：`querySecuQuote`

适用：

* 股票、指数实时行情、历史行情、当前价格、涨跌幅、成交额等字段查询。

业务参数：

* `secuNames` 或 `secuCodes`

示例：

```json
{
  "secuNames": ["贵州茅台"]
}
```

或：

```json
{
  "secuCodes": ["600519"]
}
```

---

### 6.2 自然语言 query 型 Tool

适用 Tool：

* `queryMarketData`

仅在用户明确查询市场、指数、行业、板块的数值指标时使用。

规则：

1. 从用户问题中提取查询对象、指标和时间范围。
2. 只构造查数型 query。
3. 不构造“怎么看”“为什么”“原因分析”类 query。

示例：

用户问：

> 白酒板块今天涨跌幅是多少？

构造：

```json
{
  "query": "查询白酒板块今天涨跌幅"
}
```

用户问：

> A 股主要指数当前点位是多少？

构造：

```json
{
  "query": "查询A股主要指数当前点位"
}
```

## 7. 公共协议参数

`requestId`、`pin`、`extParams` 属于 MCP Gateway 层公共协议字段，原则上由系统层或运行环境自动填充。

Skill 只负责业务参数构造，不向用户暴露这些字段。

如运行环境要求显式传入：

* `requestId`：由 Agent 或系统生成。
* `pin`：默认不手动构造，不编造用户身份。
* `extParams`：无特殊要求时传空对象 `{}`。

---

## 8. 返回结果解析规则

多数财富 MCP Tools 返回统一外层结构：

```json
{
  "code": "...",
  "success": true,
  "message": "...",
  "class": "...",
  "data": "..."
}
```

处理规则：

1. 先检查 `success`。
2. 再检查 `code`。
3. 如果 `success=false` 或 `code` 表示失败，读取 `message`，说明工具未成功返回，不得自行补数据。
4. 如果 `data` 是字符串，应二次解析为 JSON。
5. 如果 `data` 无法解析为 JSON，则按文本结果处理。
6. 不展示完整原始 JSON，除非用户明确要求。
7. 只提取与用户问题直接相关的字段。
8. 字段缺失时说明“当前工具未返回该字段”，不得猜测。

## 9. 指标字段提取规则

当 Tool 返回较大 JSON 时，只提取用户询问的指标及必要辅助字段。

### 基金类

优先提取：

* 基金名称
* 基金代码
* 用户询问的目标指标
* 基金类型
* 风险等级
* 基金经理
* 基金规模
* 单位净值 / 累计净值
* 实时估值
* 估值涨跌幅
* 数据日期 / 估值时间

### 股票 / 指数类

优先提取：

* 股票 / 指数名称
* 代码
* 用户询问的目标指标
* 当前价格 / 当前点位
* 涨跌额
* 涨跌幅
* 成交额 / 成交量
* 市值
* PE / PB，如返回中存在
* 数据时间

### 黄金类

优先提取：

* 黄金品类
* 用户询问的目标指标
* 当前价格
* 涨跌额
* 涨跌幅
* 计价单位
* 报价时间

### 市场 / 板块类

优先提取：

* 市场 / 板块 / 行业名称
* 用户询问的目标指标
* 当前点位 / 当前价格
* 涨跌额
* 涨跌幅
* 成交额 / 成交量
* 数据时间

## 10. 模糊匹配处理规则

部分 Tools 可能自带模糊匹配，并默认返回相似度最高结果。

处理原则：

1. 如果返回对象与用户输入高度一致，可以继续回答。
2. 如果返回对象与用户输入不完全一致，应说明“系统匹配到的是 xxx”。
3. 如果返回多个候选，应列出候选并请用户确认。
4. 如果只返回一个候选，但名称、代码、类型与用户输入明显不一致，应向用户确认。
5. 标的不确定时，不得继续调用后续分析、推荐或交易类工具。
6. 不得默认选择第一个候选作为最终对象，除非返回结果明确说明该对象为唯一高置信匹配。

## 12. 输出规范

### 总体要求

1. 只回答用户询问的指标，不主动展开分析。
2. 不输出行情诊断、涨跌原因、投资建议。
3. 不展示技术字段名、原始 JSON、内部 class、debug 信息。
4. 不展示 MCP URL、接口路径、系统调用细节。
5. 不编造工具未返回的数据。
6. 不使用“稳赚”“保本”“必涨”等确定性表述。
7. 涉及实时数据时，应展示数据时间或报价时间。
8. 涉及金融产品时，应附带简短风险提示。
9. 输出结构应简洁，不强制固定模板。

### 推荐输出结构

```text
查询对象：xxx

指标结果：
- 指标名称：xxx
- 指标值：xxx
- 数据时间：xxx

补充说明：
- 如工具返回匹配对象、单位或口径，可简要说明。

风险提示：
以上信息仅供参考，不构成投资建议。
```

如果用户一次查询多个指标，可以按表格或短列表输出，但不要主动扩展无关字段。

---

## 13. 错误处理

### 工具调用失败

如果 Tool 返回失败：

1. 说明工具未成功返回。
2. 可展示 `message` 中适合用户理解的信息。
3. 不编造结果。
4. 建议用户提供更明确的代码、名称或时间范围。

### data 解析失败

如果 `data` 字段无法二次解析：

1. 如果 data 是可读文本，则只提取其中与指标相关的信息。
2. 如果 data 不可读，则说明当前返回结果无法解析。
3. 不把不可解析内容包装成确定性数据。

### 多候选不确定

如果返回多个候选：

1. 列出候选名称、代码、类型。
2. 请用户确认。
3. 用户确认前，不继续做后续查询。

## 14. 示例流程

### 示例 1：基金估值查询

用户：

> 005827 现在估值多少？

流程：

1. 判断为基金估值查询。

## 15. 常见问题

### 1. 用户问“能买吗”怎么办？

不使用本 Skill 直接回答。提示用户本 Skill 仅支持指标查询，如需投资分析需进入分析研究类 Skill。

建议回复：

> 我可以先帮你查询相关指标，例如价格、估值、风险等级或涨跌幅。是否适合买入需要结合更多分析，不能仅凭单一指标判断。

### 2. 用户问“为什么涨跌”怎么办？

不使用本 Skill 解释原因。应转入行情诊断、市场情报或分析研究类 Skill。

### 3. 用户问“什么是某指标”怎么办？

本 Skill 不负责概念解释。应转入指标解释或 FAQ 类 Skill。

### 4. 用户只给简称怎么办？

先调用对应 Tool 尝试识别。如返回多个候选，应让用户确认；如只返回一个但不确定，应说明系统匹配到的对象。

### 5. 返回 JSON 很大怎么办？

不要完整展示。只提取用户询问的指标、匹配对象、单位、口径和数据时间。
